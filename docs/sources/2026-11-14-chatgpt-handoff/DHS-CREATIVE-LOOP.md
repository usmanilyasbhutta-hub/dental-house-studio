# DHS Creative Loop — Create → Inspect → Diagnose → Improve

**Status:** Active operating checklist  
**Purpose:** Make DHS content creation, critique and iteration repeatable without creating a second design authority.  
**Updated:** 21 October 2026

## Authority
This file governs **how creative work is prototyped, inspected, diagnosed and revised**. It does not define the DHS brand.

Precedence:
1. current explicit owner decision,
2. clinical truth / consent / privacy / factual accuracy,
3. `DESIGN.md` — visual and motion authority,
4. `WORKFLOW.md` — production / approval / handoff sequence,
5. `ASSETS.md` — authentic source assets,
6. current strategy / calendar / playbook,
7. this file for operational critique mechanics,
8. external design/motion references for inspiration only.

If this file conflicts with `DESIGN.md` or `WORKFLOW.md`, this file loses.

---

## Loop overview
**Brief → Art direct → Prototype → Produce → Cold QA → Diagnose → Correct → Compare → Learn**

Do not skip directly from brief to polished full production when the concept or motion language is materially new.

## A. Brief
Capture only what the asset needs:
- campaign/topic and objective,
- audience moment / campaign DNA,
- one viewer payoff,
- one primary CTA,
- DHS anchor,
- authentic proof available,
- asset-role plan,
- format and platform constraints.

Ask the 4–6 campaign-DNA questions from `DESIGN.md` only when materially unresolved.

## B. Art direction
Before layout/editing:
- one-sentence visual concept,
- composition/reference direction,
- hero,
- typography role,
- campaign world,
- authentic proof role,
- continuity decision where relevant,
- what must remain recognisably DHS.

For video also define:
- calm ↔ kinetic,
- soft ↔ sharp,
- timing scale,
- easing behaviour,
- transition family,
- stagger rhythm if needed,
- motion hierarchy: **Hero / Support / Texture**,
- what intentionally stays still.

## C. Prototype first
### Static/carousel
Build one representative hero/cover or interior slide before extending a new system.

### Video
Build a 2–3 second opening prototype or a short 3–5 second motion test when the motion language itself is new.

Reject weak concepts before producing the whole asset.

## D. Produce
Use `DESIGN.md` and `WORKFLOW.md`.

Core rule:
**real where it proves; designed/illustrative where it frames; repetition only when it adds new information.**

Do not generate proof. Do not replace usable authentic DHS footage simply because synthetic media is easier.

## E. Cold QA
### Universal checks
1. **2-second first impression** — what wins first?
2. **Phone-size** — is hierarchy/readability intact?
3. **Without-logo** — still DHS? still clearly clinical/dental?
4. **Truth/source** — proof real, illustration non-documentary?
5. **Asset-role** — does each image/clip perform a new job?
6. **Restraint** — what can be removed with no loss?
7. **CTA** — is the intended next action obvious and proportionate?

### Carousel/static checks
- inspect the cover alone,
- inspect each slide at phone size,
- inspect all thumbnails together,
- verify purposeful progression,
- check continuity without duplicated media roles,
- confirm quiet typography-led frames are allowed to remain quiet.

### Video checks
Inspect the **actual export**, not only the editor timeline.

When tooling allows, create a representative contact sheet:
- opening: roughly 0s / 1s / 2s,
- midpoint,
- payoff,
- final CTA,
- adapt sampling to the actual runtime.

Then ask:
- Is the opening visually different enough to create an expectation?
- Does every sampled frame have a clear focal priority?
- Is the composition repeating without progress?
- Does the hero motion win over support/texture?
- Does kinetic type clarify meaning/rhythm or merely create activity?
- Are transitions motivated by action, camera, mask, occlusion, sound or concept?
- Is there enough stillness?
- Does the payoff visually fulfil the setup?
- Does the CTA feel like part of the piece rather than a template outro?

Watch once **sound-on** and once **muted**.

## F. Diagnose before editing
Tag the main problem:
- **Concept**
- **Hierarchy**
- **DHS identity**
- **Category identity**
- **Asset role**
- **Typography**
- **Motion**
- **Pacing**
- **Sound**
- **Proof**
- **CTA**

### Severity
- **Blocker:** truth/privacy/consent/clinical misrepresentation, wrong brand asset, unreadable or misleading output.
- **Major:** weak concept, wrong hierarchy, generic identity, redundant asset logic, dated motion, poor pacing, weak payoff.
- **Minor:** optical spacing, small crop, micro-typography, subtle polish.

Fix blockers and major issues before minor polish.

## G. Correct
Use **Preserve / Modify / Renew**.
- **Preserve:** keep approved strong layers untouched.
- **Modify:** repair the diagnosed weak layer only.
- **Renew:** rebuild when the concept itself is the problem.

Do not solve every criticism at once. Avoid making a piece sloppier by stacking corrections.

## H. Compare
Whenever a meaningful revision is made:
- compare old vs revised side-by-side,
- state what changed,
- judge the same cold-review criteria,
- prefer the output that communicates better, not the one with more effects.

If neither clearly wins, renew the weak layer rather than polishing indefinitely.

## I. Learn without bloating the master
Record:
- what failed,
- diagnosis tag,
- what changed,
- whether the revision improved the output,
- whether the pattern repeated successfully elsewhere.

A single good execution stays a **campaign lesson**.  
A pattern may graduate into `DESIGN.md` only when:
- it works across materially different briefs,
- it clearly strengthens DHS identity/communication, or
- the owner explicitly adopts it as a durable rule.

External public design/motion skills remain **craft references**, not governing DHS rulebooks.

---

## Output-over-compliance rule
**The finished output is the test.**

A creative can follow every listed rule and still fail if it feels generic, dated, over-designed, AI-made, unclear or unlike DHS. Conversely, a strong deliberate exception may be valid when it preserves clinical truth and the owner explicitly approves it.

The checklist exists to improve judgement, not replace it.
